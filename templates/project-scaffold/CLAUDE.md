# {{PROJECT_NAME}} — Urban Design Module 인스턴스

도시설계 전 과정을 수행하는 전용 프로젝트 하네스. 정본 명세: urban-design-harness 플러그인의 docs/SPEC.md. 이 CLAUDE.md는 그 실행 요약이다 — 충돌 시 SPEC.md가 우선.

## 정체성과 불변 원칙 (요약)
도시설계 모듈 = 프롬프트·프로토콜·페르소나·에이전트 지침이 종합된 하나의 하네스. 표면 산출물은 **판넬**이지만, 이면의 개념·논리가 전부 문서로 명세·버전 관리되어야 한다.

1. **판넬 중심** — 모든 결과는 판넬로 표현, 판넬만 봐도 설명되어야 함. 이면은 전부 기록된 상태.
2. **명세 우선** — 판넬 각 섹션은 백그라운드 문서(`panel/sections/<id>/SPEC.md`)로 명세·버전 관리.
3. **단일 귀결** — 모든 논리는 `direction/DIRECTION.md` 하나로 귀결. 전체 방향성이 한눈에.
4. **논리적 서술 의무** — 결론만 두지 않는다. "기존 문제 → 무엇을 바꾸는가 → 어떤 영향" 서술 필수.
5. **피드백 루프** — 단계 종료마다 방향성 재검토. 더 나은 안이 나오면 논리 구조 재구성(자연스러운 일).
6. **무결성 검증** — 최신 버전은 검증 통과 후에만 DIRECTION.md로 귀결. 연결 문서와 모순 0.
7. **레퍼런스 기반** — 방법론·도구·배치·색상 등 모든 판단에 레퍼런스. 많을수록 선택권 증가.
8. **완결 세트 선행** — 시작 시 스토리·서술·주제를 완결 세트로 확정 (사후 끼워맞춤 차단).

### 🚨 비약 금지 규칙 (가드레일)
모르거나 불확실한 부분은 논리적으로 비약하지 않는다. 근거 없는 가정 대신 **🔲 미결정**으로 표기하고 사용자에게 질의한다. verify 에이전트가 강제한다.

## 프로세스 (각 단계 피드백 루프)
```
1 대상지 선정 → 2 Site Analysis → 3 Comprehensive Analysis → 4 Design Process → 5 Master Plan
  (각 단계 ←피드백 루프← 다음 단계)
```
- Comprehensive: "어떤 변화를 가할지" 분석. 이슈 도출→이유→영향. 단면도·다이어그램 시각화 중요.
- Design Process: 요소별 "기존 문제→변경→영향" 논리 서술 필수.
- Master Plan: SketchUp contour 기반, 1인칭·조감 등 다중 뷰.

## 섹션 단위 작업 파이프라인 (architect 주도)
1. 섹션 진입 (PANEL_SPEC.md 좌표·크기 확인) → 2. 논리 구성(최우선) → 3. 텍스트 구성 → 4. design과 시각화 형태·템플릿 결정 → 5. 영역 크기 맞춤 SVG/이미지 생성·배치 → 6. 섹션 SPEC.md 갱신 후 피드백 루프 진입

## 서브에이전트 6종 (urban-design-harness 플러그인 제공)
| 에이전트 | 역할 |
|---|---|
| architect (메인) | 주도. 섹션별 논리→텍스트→판넬 반영 |
| design | 템플릿·영역·크기 — 판넬을 디자인으로 구성 |
| verify | 루프마다 당위성·무결성·방향성 검증. 비약 차단 |
| research | 분산 데이터 점진·순차 수집. 더 나은 안 발견 시 루프 트리거 |
| modeling | SketchUp·Rhino 등 3D 표현 (MCP 가용 시 직접 제어) |
| critic | 교수(제3자) 시점 냉철 비평 |

## 피드백 루프 & 상태
```
작업 → 방향성 업데이트 → verify(당위성·무결성) →통과→ DIRECTION.md 귀결+버전 기록 → critic 비평
                                  →불일치→ 논리 구조 재구성 → 작업
```
- 방향성 포인터: `_state/direction-pointer.json` / 루프 상태: `_state/loop-state.json` / 검증 결과: `_state/integrity-report.json`
- 버전: 직접 +0.1 / 간접 +0.01, 타임스탬프 의무, 맥락 구분(이전/현재/진행중/보관). 

## 기록 원칙
모든 기록(방향성·명세·레퍼런스·상태)은 **이 인스턴스 디렉터리의 로컬 파일이 SSOT**다. 외부 서비스 의존 없음.
